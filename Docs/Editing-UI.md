# Редактирование интерфейса

После сборки новых C++-классов и открытия редактора модуль `labyEditor`
создаёт недостающие ассеты в `Content/UI`. Существующие файлы не перезаписываются.
Первое создание отмечается в Output Log строками `Laby editable UI created`.
Сохранённые `.uasset` нужно хранить вместе с проектом в системе контроля версий.

В Content Browser откройте папку `UI`, затем нужный Widget Blueprint и вкладку Designer:

| Ассет | Назначение |
| --- | --- |
| WBP_HUD | HUD: прицел, выносливость над здоровьем, сообщения и версия |
| WBP_ExplorationMap | Игровая мини-карта с компасом и открытая карта M |
| WBP_MainMenu | Главное меню |
| WBP_PauseMenu | Меню паузы |
| WBP_Settings | Видео, управление и параметры HUD/камеры |

Перемещайте элементы, меняйте размеры, отступы, Anchors, шрифты, цвета,
тексты кнопок и изображения. Затем нажмите Compile и Save.
Изменения видны при следующем создании виджета: меню можно закрыть и открыть,
HUD — пересоздать при следующем запуске игры. Не требуется пересборка C++ для оформления.

## Связь оформления с кодом

Сохраните родительский класс `MazeHUDWidget` для HUD и `MazeMenuWidget` для меню.
Не переименовывайте ассеты: контроллер и HUD загружают их из `/Game/UI`.
Папка добавлена в `DirectoriesToAlwaysCook`, чтобы интерфейс попал в сборку игры.

Имена следующих элементов используются кодом. Их можно перемещать и оформлять,
но при переименовании связь с данными или действием исчезнет:

| Элементы | Тип / роль |
| --- | --- |
| ResumeButton, NewGameButton, SettingsButton, BackButton, QuitButton, ResetButton | Button: действия меню |
| SensitivitySlider | Slider: чувствительность |
| SensitivityText | Text Block: значение чувствительности |
| HUDContent | Контейнер всего HUD; скрывается при открытии меню или большой карты |
| VitalsPanel | Контейнер здоровья и выносливости |
| HealthText, StaminaText | Text Block: подписи показателей; выносливость показывает восстановление |
| HealthValueText, StaminaValueText | Text Block: числовые значения из ECS |
| HealthBar, StaminaBar | Progress Bar: заполнение из ECS |
| VersionText | Text Block: ALPHA и версия проекта |
| DeathPanel, ExitPanel | Контейнеры сообщений; по умолчанию Collapsed |
| ExitText | Text Block: номер достигнутого выхода |
| MinimapBounds, FullMapBounds | В WBP_ExplorationMap: границы игровой мини-карты и открытой карты |

Runtime обновляет текст значений и заполнение полосок. Для смены цветов выносливости
используйте `Stamina Color` и `Exhausted Color` в Class Defaults HUD.
Цвет здоровья задаётся на `HealthBar` в Designer.

Карта разработчика F7 удалена вместе с нативным классом и состоянием переключения.
Игровая карта остаётся в WBP_ExplorationMap; подсказка M КАРТА находится над
мини-картой слева. На рамке компаса направление обозначают три круглые точки.
Для оформления сообщений о смерти/выходе временно включите их Visibility в Designer,
затем верните Collapsed; во время игры видимость управляется состоянием ECS.

Логика здоровья, выносливости, генерации, прогресса и сеанса остаётся в Mass ECS.
Виджеты читают снимки данных и передают действия контроллеру. Не добавляйте в них
второе независимое состояние игры. Обработчики стандартных кнопок подключаются
нативным классом: дублировать те же действия через Blueprint OnClicked не нужно.

## Первое подключение

Для этой миграции нужен закрытый редактор и полная сборка `labyEditor Win64 Development`:
добавлены UMG, новые отражаемые классы и editor-модуль. После сборки откройте проект
обычным способом и дождитесь создания ассетов. Live Coding применяется
к последующим совместимым правкам C++, но не заменяет эту первоначальную сборку.

Editor-модуль не создаёт файлы во время cook или других commandlet-запусков.
Перед упаковкой проекта ассеты должны быть созданы и сохранены обычным редактором.

## Автоматический Live Coding

Editor-модуль наблюдает за сохранениями файлов `Source` раз в секунду.
После изменения существующего `.cpp` и пяти секунд без новых изменений он
запрашивает Live Coding через API редактора. Параллельные компиляции не запускаются;
изменения во время сборки остаются для следующего запроса. Ошибка сборки не вызывает
бесконечных повторов: новый запрос появляется после следующего сохранения.

Изменение заголовков, build rules, `.uproject`, добавление или удаление файлов
приостанавливает автоматические запросы до проверки совместимости. Это не означает,
что каждый заголовок требует перезапуска: совместимые изменения можно применить
ручным Live Coding. Изменения зависимостей требуют полной сборки с закрытым редактором.

Команды Output Log:

- `laby.AutoLiveCoding 0` — отключить автоматические запросы.
- `laby.AutoLiveCoding 1` — включить их для последующих сохранений.
- `laby.AutoLiveCodingDelay 8` — изменить задержку на восемь секунд (минимум две).

После проверки заголовков отключите автокомпиляцию на пару секунд и включите снова,
чтобы снять приостановку. Обычный Ctrl+Alt+F11 продолжает работать независимо.
Автокомпиляция не запускает Play, не перезапускает редактор и не вызывает Build.bat.
Для первоначального подключения самого наблюдателя также требуется полная сборка.

## Зелёное стекло / единое оформление

Оформление основано на одобренных пользователем концептах HUD и карты: тёмное
стекло, серо-зелёные акценты под пол лаборатории, тонкие рамки, лёгкие шрифты.
Обновлены все пять Widget Blueprint, включая главное меню, паузу, три страницы
настроек, HUD, мини-карту, открытую карту и сообщения о смерти/найденном выходе.
Предыдущие дуговые панели больше не используются этими макетами.
В главном меню оставлены бренд и действия, без заголовка «Главное меню».
Здоровье и выносливость — две непрерывные тонкие шкалы с отдельными числовыми
значениями справа, без квадратных рамок и значков. Компактный режим скрывает подписи и числа.

`Source/labyEditor/Private/UI/MazeGlassUIAssets.cpp` — редакторский автор макетов.
Команда `laby.UI.ApplyGlassStyle` явно заменяет деревья меню и HUD, обновляет карту
и сохраняет Widget Blueprint. Она отказывается работать во время Play; автоматически
при старте редактора существующие макеты не заменяются. Перед ручным повторным
применением сохраните собственные правки виджетов. Копии предыдущих пяти ассетов
этой итерации находятся в `Saved/UIBackups/BeforeGlass-20260920`.

`laby.UI.PreviewGlassStyle` экспортирует статические 1920×1080 снимки всех экранов,
три страницы настроек, сообщения Death/Exit, Loading, HUD с примером мини-карты,
отдельную мини-карту и меню 1280×720 в `Saved/UI/GlassPreview`. Это Designer-рендер
без Play, запуска мира и ECS. Иллюстрация топологии на этих снимках фиксированная;
она не сохраняется в игровой карте и не подменяет данные во время игры.
Предпросмотр учитывает скрытые состояния на временных экземплярах до создания
Slate-дерева: сообщения смерти/выхода и отладочные поля не перекрывают обычный HUD.
Экспорт использует FloatRGBA render target и однократное преобразование линейных
цветов в sRGB: это сохраняет оттенки палитры и детали тёмного фона. Для ScaleBox
выполняется второй проход layout; меню 1280×720 создаётся отдельным экземпляром.

Общие цвета и Slate-шрифт — `UI/MazeInterfaceStyle.h/.cpp`. Макеты остаются
редактируемыми UMG Widget Blueprint. Используются штатные `UButton` brush states,
UMG controls, ScaleBox и Slate. CommonUI не добавляется: маршрутизация устройств
не менялась. RetainerBox, SceneCapture и дополнительная 3D-сцена не нужны.
Фон меню — отдельная текстура `/Game/UI/Glass/T_MenuBackdrop`, без запечённых
кнопок или надписей. Исходник и окончательный запрос imagegen лежат в
`ArtSource/UI/Glass`. В игре HUD накладывается на настоящий уровень.

Круглый курсор использует текущий UE `SetSoftwareCursorWidget` со Slate-виджетом.
Единственный системный указатель принадлежит viewport; его регистрирует первый
локальный игрок и освобождает при EndPlay. Анимация заполнения зависит только
от наведения на доступный Slate control; она не активирует кнопки автоматически,
не удерживает ссылки на виджеты или мир и не является игровым состоянием.
Для наведения/нажатия применены штатные `FButtonStyle` sounds, короткие оригинальные
эффекты из `Scripts/create_ui_sounds.py`. Клавиатурная навигация сохраняется.
Загрузка использует ту же палитру и типографику в чистом Slate: MoviePlayer может
рисовать её при занятом игровом потоке, без UObject-привязок или UMG Tick.

## Настройки и привязки

- Видео: общий уровень качества, тени, лимит FPS, масштаб рендера и VSync.
  Применяются существующие `UGameUserSettings::ApplyNonResolutionSettings` и SaveSettings.
  Разрешение и режим окна не переключаются.
- Управление: чувствительность и инверсия Y; десять UInputKeySelector в двух
  столбцах для движения, бега, прыжка, приседа, фонарика, карты и нового лабиринта.
- Игра: компас по краям карты, центральная точка и покачивание камеры.
  Поле зрения и компактные показатели убраны из меню.

Все разделы применяют и сохраняют изменения сразу. Кнопки «Применить» и пояснения
про отмену нет; «Исходные» немедленно сбрасывает доступные настройки и клавиши.
Программное заполнение контролов защищено от повторных обработчиков и записи.
Чувствительность принадлежит UMazePreferences,
остальные локальные параметры — Maze.InterfacePreferences в GameUserSettings.ini.
Они не реплицируются и не дублируют игровой ECS-state. Скрытые прежние параметры
FOV/CompactHUD сохраняют свои значения, меню их не перезаписывает.

Привязками владеет штатный UInputSettings; MazeKeyBindings читает и обновляет
именованные action/axis mappings и сохраняет их в пользовательский GInputIni.
ForceRebuildKeymaps обновляет живой PlayerInput. При изменении сбрасываются
нажатые клавиши контроллера и прежний ввод ECS. При первом локальном SetupInputComponent
добавляются отсутствующие действия для старого пользовательского Input.ini.
Esc отменяет захват клавиши; занятые и служебные клавиши отклоняются с текстом
в KeyBindingStatus. Назначения карты учтены в открытии, закрытии и подсказках.
Штатный Enhanced Input User Settings проверен в UE 5.8, но предназначен для
player-mappable Input Actions/Contexts. Проект пока связывает именованные legacy
action/axis mappings, поэтому здесь использован подходящий UInputSettings без
параллельного контекста и миграции игрового ввода. UInputKeySelector также штатный.

Существующие имена: MainMenuButton, VideoTabButton, ControlsTabButton, GameTabButton,
SettingsPages (WidgetSwitcher), QualityCombo, ShadowsCombo,
FrameLimitCombo, RenderScaleSlider/Text, VSyncCheck,
InvertYCheck, CompassCheck, CrosshairCheck, CameraMotionCheck,
Binding_<Id> (InputKeySelector), Binding_<Id>Label, KeyBindingStatus.

Длинные названия клавиш рисует `MazeKeyLabelScroll.cpp` поверх штатного
InputKeySelector, сохраняя его захват ввода и оформление кнопки. Текст обрезается
границами поля и движется туда-обратно со скоростью 32 Slate-единицы/с, с паузой
1 с у каждого края; короткие подписи остаются по центру. Это локальная анимация
интерфейса на NativeTick, работающая и в меню паузы. Смена текста или ширины поля,
уход с вкладки управления и уничтожение меню сбрасывают состояние прокрутки.
Список Id находится в MazeKeyBindings::Definitions. SettingsSectionTitle и индикаторы вкладок с суффиксом
Indicator. Нативные обработчики не дублируются Blueprint-графами.

## Карта и данные

`UMazeExplorationMapWidget` читает готовую топологию и исследование из ECS, положение
персонажа и направление камеры из прежних источников. `MazeMapPaint` синхронно
рисует только эти заимствованные данные, без сохранения указателей между кадрами.
Maze handle/revision продолжают проверяться. Неисследованные клетки, выходы и
провалы не раскрываются, даже если концепт-картинка показывала пунктир за границей.

Контент обеих карт строится одним рендерером: исследованные коридоры показаны
цельными полосами со скошенными углами, тёмными промежутками стен и соединённым
контуром без швов между клетками. Заливка пакетируется через штатный Slate
`MakeCustomVerts`, без SceneCapture, новых текстур или игрового состояния.
Пунктир отмечает только границу уже исследованной клетки с открытой стороной;
соседний неизвестный коридор не рисуется. Треугольник игрока и мягкий сектор
взгляда — залитые фигуры. Векторные обозначения легенды соответствуют карте.

N (-Y), E (+X), S, W размещены по краям квадрата. Карта не вращается; зелёный
маркер и слабый сектор показывают направление взгляда. Мини-карта — 312×312
логических единиц с редактируемым MinimapBounds. FullMapBounds задаёт всю область
открытой карты: легенда слева, квадрат с коридорами справа, подсказки снизу.
`MazeMapContentRect` используется и отрисовкой, и масштабированием вокруг мыши,
так что смещение квадрата относительно центра экрана не ломает zoom anchor.
ЛКМ перемещает карту, колесо масштабирует, Home возвращает к игроку, M/Esc закрывает.
При открытой карте обычный HUD скрывается. F7 остаётся отдельной отладочной картой.

Авторитетное состояние, правила, расписание и жизненный цикл ECS не менялись.
Игровая проверка и оценка звука/курсора при реальном вводе остаются за пользователем;
статический предпросмотр не является проверкой игрового поведения.
