# Здоровье и стамина

Внизу слева отображаются здоровье и стамина (0–100).

- Shift + движение по земле: бег со скоростью 750 см/с вместо 450 см/с, расход 20 стамины/с. Стояние и обычная ходьба не расходуют стамину.
- Прыжок: 15 стамины за успешный отрыв от земли. Если стамины меньше 15, прыгнуть нельзя. Неудачные попытки и удержание Space не списывают дополнительные очки.
- Восстановление: 15/с при ходьбе или стоянии на земле после 1,5 секунды с последнего расхода. В воздухе стамина не восстанавливается, но задержка продолжает отсчитываться.
- При истощении включается шаг, шкала становится оранжевой. Бег снова доступен с 25 стамины; если Shift всё ещё зажат, он возобновится автоматически.
- Здоровье принимает стандартный урон Unreal через TakeDamage / ApplyDamage. Отрицательный урон не лечит. Новые источники урона и автоматическое лечение пока не добавлены.
- При нуле здоровья движение и прыжки прекращаются, появляется сообщение о смерти. R запускает новый лабиринт; Escape открывает меню.
- Новая игра возвращает обе шкалы к 100. Логика рассчитана на текущую одиночную игру, сетевой синхронизации показателей нет.

Параметры находятся в `Source/laby/MazeVitals.h`, правила — в `MazeVitalsSystem.h`. Существующая автоматическая проверка `Laby.Character.Vitals` адаптирована к системным функциям; в этой итерации тесты не запускались по просьбе пользователя.

## Основа ECS

Используется встроенный Unreal Mass Entity (модули `MassCore` и `MassEntity`).

- Entity: отдельная `FMassEntityHandle` для каждого персонажа. Создаётся в BeginPlay, удаляется в EndPlay. Новая игра создаёт новую сущность с полными показателями.
- Components: `FMazeVitalsFragment` хранит только данные здоровья/стамины, `FMazeLocomotionFragment` — состояние бега и контакта с землёй. Источник данных — Mass Entity Manager текущего мира, копии состояния в персонаже нет.
- Systems: `UMazeVitalsSubsystem` выполняет Mass query по сущностям с обоими фрагментами раз в игровой кадр. `FMazeVitalsSystem` содержит правила расхода, восстановления, прыжка и урона без собственного состояния. При паузе обновление останавливается.
- Bridge: `AMazeCharacter` хранит идентификатор сущности, передаёт состояние CharacterMovement и события прыжка/урона. HUD получает снимок данных, не хранит указатели на память фрагментов.

Обновление работает синхронно на игровом потоке через World Subsystem; автоматический граф Mass Processors и параллельное выполнение пока не используются. Стоимость прыжка списывается сразу после подтверждения прыжка CharacterMovement. Запрет прыжка и выбор скорости читают состояние ECS. Удалённые идентификаторы проверяются через Entity Manager перед доступом.

Это гибридная основа ECS для показателей игрока. Камера, физическое движение, меню и процедурная геометрия лабиринта остаются Actor/Component-кодом Unreal. Новые ECS-механики следует добавлять отдельными фрагментами и системами, связывая их с Actor только там, где требуется API движка. Репликация ECS-состояния пока не реализована.

Первое подключение требует полной сборки с закрытым редактором: изменены зависимости модуля, добавлен World Subsystem и Mass-фрагменты. После сборки открыть редактор и заново запустить Play. Live Coding для этого первого перехода не используется.
